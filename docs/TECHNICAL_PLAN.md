# IZMI — технический план

Версия: 0.1  
Статус: архитектура первого прототипа

## 1. Выбранный движок

**Unity 6 LTS**

Основной язык: **C#**  
Рендеринг: **Universal Render Pipeline (URP)**  
Целевая платформа прототипа: **iPhone / iOS**  
Дополнительная тестовая платформа: ПК в редакторе Unity

### Почему Unity

- зрелая поддержка мобильной 3D-графики;
- удобная сборка под iOS;
- инструменты LOD, профилирования, освещения и оптимизации;
- поддержка GPU instancing;
- возможность использовать Entities/DOTS для большого количества однотипных объектов;
- большой выбор совместимых 3D-ресурсов и инструментов;
- C# позволяет поддерживать понятную модульную архитектуру.

### Почему не Unreal Engine

Unreal способен дать сильную графику, но для первой самостоятельной мобильной игры создаёт лишнюю сложность, большой размер проекта и более тяжёлые требования к производительности.

### Почему не Godot

Godot подходит для небольших игр, однако для масштабируемой трёхмерной Земли, мобильной оптимизации и больших потоков однотипных объектов Unity даёт более подходящий набор готовых инструментов.

## 2. Главная цель прототипа

Проверить единую непрерывную сцену:

**3D-планета → выбор точки → приближение → загрузка города → живая улица → локальное заражение → отдаление к планете.**

Прототип считается успешным, если этот переход:

- визуально убедителен;
- не вызывает заметных зависаний;
- работает на реальном iPhone;
- сохраняет состояние города после отдаления;
- позволяет повторно приблизиться и увидеть последствия.

## 3. Архитектура масштаба

Мир разделён на логические уровни представления.

### Уровень 0 — планета

- сфера Земли;
- атмосфера и облака;
- смена дня и ночи;
- точки городов;
- глобальные маршруты;
- агрегированные данные регионов.

### Уровень 1 — регион

- упрощённый рельеф;
- основные дороги;
- города и поселения;
- воздушные и наземные потоки;
- зоны контроля и заражения.

### Уровень 2 — город

- дорожная сеть;
- кварталы;
- основные объекты;
- транспортные потоки;
- визуальное состояние кризиса.

### Уровень 3 — улица

- люди;
- машины;
- зомби;
- животные;
- спецтехника;
- локальные события;
- простое поведение агентов.

Это не четыре одновременно загруженных мира. Система камеры и потоковой загрузки заменяет далёкие представления более подробными по мере приближения.

## 4. Два слоя симуляции

### Стратегическая симуляция

Работает независимо от камеры и хранит истинное состояние мира:

- население;
- заражённые;
- погибшие;
- ресурсы;
- инфраструктура;
- паника;
- транспортные потоки;
- решения руководителей;
- развитие инфекции.

Этот слой использует компактные данные и способен рассчитывать множество городов.

### Визуальная симуляция

Создаётся рядом с камерой и показывает стратегические данные:

- машины;
- толпы;
- заражённых;
- пожары;
- пробки;
- блокпосты;
- отключённые районы;
- работу экстренных служб.

Визуальные агенты не являются всем населением города. Они представляют его текущее состояние.

## 5. Основные модули

### WorldClock

- игровое время;
- пауза;
- множители скорости;
- замедленное время вне игры;
- ограничение необратимых событий в отсутствие игрока.

### GlobeSystem

- вращение планеты;
- масштабирование;
- выбор регионов;
- отображение глобальных событий;
- переход между уровнями детализации.

### RegionSimulation

- состояние стран, регионов и городов;
- миграция;
- ресурсы;
- инфраструктура;
- распространение инфекции.

### CityStreaming

- загрузка и выгрузка города;
- процедурная сборка кварталов;
- восстановление сохранённого состояния;
- подготовка объектов по данным симуляции.

### TrafficSystem

- маршруты машин;
- плотность движения;
- пробки;
- аварии;
- эвакуационные и военные колонны.

### CrowdSystem

- обычные жители;
- паника;
- эвакуация;
- поиск убежища;
- заражение;
- превращение в зомби.

### InfectionSystem

- стадии болезни;
- способы передачи;
- заражение людей и животных;
- заражённая среда;
- мутации;
- агрегированный и локальный расчёт.

### CrisisOrders

- решения игрока;
- постоянные приказы;
- автоматические пороги;
- исполнение на уровне регионов и объектов.

### OfflineSimulation

- сохранение времени выхода;
- расчёт прошедшего периода;
- постепенное замедление;
- журнал произошедших событий;
- защита от окончательного поражения без игрока.

### Chronicle

- хроника отсутствия;
- фильтрация важных событий;
- переход камеры к месту события;
- визуальное воспроизведение ключевых изменений.

### SaveSystem

- версия сохранения;
- состояние мира;
- состояние городов;
- настройки игрока;
- защита от повреждённых данных;
- резервная копия последнего корректного состояния.

## 6. Подход к производительности

- URP вместо тяжёлого рендеринга;
- уровни детализации моделей;
- impostor-объекты и упрощённые модели вдали;
- GPU instancing для повторяющихся зданий и транспорта;
- object pooling для людей, машин и эффектов;
- ограничение активных агентов вокруг камеры;
- агрегированная симуляция вне текущего города;
- асинхронная загрузка;
- минимальное количество прозрачных материалов;
- запечённое освещение там, где это возможно;
- динамические тени только рядом с камерой;
- профилирование на реальном iPhone с ранних этапов.

Entities/DOTS не используется для всей игры с первого дня. Сначала создаётся понятный прототип на обычных Unity-компонентах. После измерений самые нагруженные системы могут быть перенесены на ECS.

## 7. Управление на телефоне

- один палец: вращение планеты и перемещение камеры;
- два пальца: масштабирование;
- касание объекта: информация и доступные действия;
- удержание: дополнительные сведения;
- жест возврата: переход на предыдущий масштаб;
- кнопки времени: пауза, обычная скорость и ускорение.

Интерфейс должен оставаться читаемым без мелкого текста и не закрывать планету.

## 8. Этапы первого прототипа

### Этап 1 — Земля

- базовый Unity-проект;
- URP;
- вращаемая планета;
- атмосфера;
- освещение;
- управление мышью и касаниями;
- точки тестовых городов.

### Этап 2 — камера и переход

- плавное приближение;
- определение уровня масштаба;
- переход от глобальной сцены к локальной;
- маскировка загрузки без чёрного экрана.

### Этап 3 — тестовый город

- дорожная сетка;
- кварталы;
- несколько типов зданий;
- вода и рельеф;
- движение машин;
- простые жители.

### Этап 4 — заражение

- один первичный заражённый;
- контактное заражение;
- стадии болезни;
- паника жителей;
- распространение по району;
- агрегирование результата.

### Этап 5 — сохранение мира

- выход из города;
- продолжение стратегической симуляции;
- возвращение;
- восстановление последствий.

### Этап 6 — iPhone

- тестовая сборка;
- измерение FPS, памяти, нагрева и расхода батареи;
- снижение нагрузки;
- определение минимального поддерживаемого устройства.

## 9. Что пока не создаём

- всю Землю с реальными зданиями;
- полноценную экономику;
- завершённые сюжетные ветки;
- десятки видов зомби;
- сетевой режим;
- аккаунты и серверную инфраструктуру;
- магазин;
- финальные 3D-модели;
- сложные боевые действия.

Эти системы добавляются только после подтверждения основной технической идеи.

## 11. Требования для iOS

Локальная финальная сборка и публикация iOS-приложения требуют macOS и Xcode. Разработку основной логики и сцен можно вести на Windows, а сборку под iPhone выполнять позднее на Mac или через сервис автоматической сборки.

Также потребуются:

- Apple Developer Account;
- зарегистрированный идентификатор приложения;
- сертификаты подписи;
- профиль распространения;
- тестовый iPhone;
- страница приложения в App Store Connect.


## 12. Разработка и мобильное тестирование на Windows

Основная разработка выполняется на Windows. Для этого проект получает два согласованных профиля запуска.

### Mobile Simulator

Используется Unity Device Simulator. Он показывает игру в корпусе выбранного iPhone и позволяет проверять:

- разрешение и соотношение сторон;
- безопасные зоны вокруг выреза и системной панели;
- поворот экрана;
- масштаб интерфейса;
- базовые мобильные взаимодействия.

Device Simulator не считается достоверным тестом производительности, нагрева, памяти и особенностей мобильного GPU.

### Windows Mobile Test Build

Проект собирается в отдельный Windows-билд, который повторяет мобильные условия:

- фиксированное мобильное соотношение сторон;
- мобильное качество графики;
- такое же ограничение количества объектов;
- такой же интерфейс;
- тот же код камеры и жестов;
- ограничение частоты кадров;
- отображение FPS и используемой памяти в тестовом режиме.

Управление адаптируется без разделения игровой логики:

| Мобильный жест | Управление на ПК |
|---|---|
| касание | левая кнопка мыши |
| движение одним пальцем | перетаскивание мышью |
| сведение и разведение пальцев | колесо мыши |
| удержание | удержание левой кнопки |
| поворот двумя пальцами | правая кнопка и движение мыши |
| системный возврат | Escape |

Unity Input System используется как единый слой ввода. Игровые системы получают не конкретные клавиши, а действия: Select, Pan, Zoom, Rotate и Back.

### Реальное тестирование iOS

Большую часть механики, интерфейса и графики можно проверять на Windows. Однако перед релизом обязательно потребуется настоящий iPhone для измерения:

- реальной производительности;
- расхода памяти;
- нагрева;
- расхода батареи;
- качества сенсорных жестов;
- поведения Metal;
- запуска после сворачивания;
- сохранения при закрытии приложения.

Если Mac отсутствует, промежуточные подписанные iOS-сборки могут создаваться через Unity Build Automation после настройки Apple Developer Account и сертификатов.
